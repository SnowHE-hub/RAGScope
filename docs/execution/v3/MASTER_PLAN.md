# RAGScope v3：先定位原因、再验证收益的 Goal 执行任务书

> 交付对象：ChatGPT 桌面版中的 Codex。执行方式：Goal + 用户已选择的 Full Access，权限以客户端实际设置为准。
> 任务性质：在本地 **当前 v2 仓库**上诊断和改进，不重建旧版项目，不把功能完成当作性能达标。
> 依据：用户上传的 `FINAL_REPORT(3).md`、`GENERATION_TABLES.md`、`粘贴的 Markdown (1).md`。附件是汇总报告和对话，不是完整的逐题 journal、训练样本或 v2 源码；涉及具体 bug 的判断必须在本地取证。
> 本任务书中的数值门槛、样本预算和超参数是本轮工程约定或待试候选，不是论文保证的最优值。不得为了达标事后降低门槛。

## 0. Goal、完成条件与自动执行合同

### 0.1 总目标

在保留 v2 数据、模型、代码和全部负结果的前提下：

1. 查清模型规模倒挂、重排退步、邻块扩展取舍、全库检索较弱、路由失效和 LoRA 退步的主要可验证原因。
2. 建立区分文字匹配、语义匹配、事实完整性、引用支持和上下文充分性的评分体系。
3. 实现并实际测试一条更可靠的问答主链；问题类型路由、重新微调等只在前置收益成立时开展。
4. 用未参与改进的新题、同一指标和同一运行条件比较冻结的 v2 基线与 v3 候选，分别报告质量和成本。
5. 仅当发布门槛满足时更新默认配置。未满足则保留 v2 默认，但必须交付已经验证的修复、明确的负结果与阻断证据。

**停止条件不是“分数不够就无限继续”，而是：所有必需阶段和已触发的条件阶段执行或有证据地阻断，预算内完成验证，留下可运行成果与真实结论。**

### 0.2 三个结果必须分开

- `workflow_finished`：所有任务已到达有证据的终态，包含安全阻断。
- `execution_complete`：所有必需项真实完成、条件项按门槛完成或合理跳过；必需项BLOCKED时必须为false。
- `performance_status`：`CONFIRMED_ON_FROZEN_METRICS / PROMISING_NOT_CONFIRMED / NO_GAIN / INCONCLUSIVE / BLOCKED`。
- `release_status`：`AUTO_VALIDATED_EXPERIMENTAL / KEEP_V2_DEFAULT / HUMAN_REVIEW_REQUIRED`。

没有人工审核时，`human_review_status` 必须为 `NOT_REVIEWED`；Codex、本地模型或另一个 AI 的审核不能改名为人工审核。自动指标通过只支持自动指标范围内的结论。

### 0.3 不再中途等用户选型

直接执行，不再询问是否下载、是否继续、选哪种库或是否进入下一阶段。普通抉择由你按任务书自主决定，写入 `DECISIONS.md` 后推进。阶段门槛由程序检查，不是等待用户点击的人工门槛。

发生障碍时依次：本地排查 → 一次修复 → 最多一次有依据的兼容替代 → 标记真实阻断并推进独立任务。不要无限重试、不断换模型，或把失败项删除。需要系统权限、付费、未知训练进程操作或人工真值的事项，不绕过边界；保存阻断而不是伪造完成。

### 0.4 工作位置、资源和最新权限

- 优先使用当前已打开且核实为 RAGScope 的仓库；候选路径：`D:\MCS_26S1课程资料\个人项目\RAGScope`。
- 所有大文件优先放 `D:\RAGScope_Runtime`。新 campaign 为 `v3_<本地日期时间>`；不要覆盖 `20261014_v2`。
- 最新报告写明用户后来允许任何阶段用 GPU，并要求 `USER_MANUAL_RESUME`。本轮不沿用旧“前两阶段一律 CPU-only”的限制；但纯审计没有必要占 GPU。GPU 有竞争时先识别并保护既有工作。
- **不得自动恢复原训练。** 本轮结束释放本项目模型、服务和锁，记录状态，由用户自行恢复。不得重建已被用户取消的定时任务。
- 对其他进程不依据“python/ollama”等名字批量结束。只有确认属于此前明确授权可暂停的训练、断点完整且正常停止方式可靠时，才可安全保存退出；否则保留该进程并使用独立可行任务。
- 不重启电脑/WSL，不改 WSL 内存上限、系统驱动、安全工具，不卸载用户已有环境，不清理无关缓存，不 push，不上传私有数据，不新增付费 API，不寻找或打印密钥。
- 复用已有 5 个虚拟环境和模型。必要的新依赖进入 `envs/v3_*`，而不是升级旧环境污染 v2。
- 不因库推荐 FlashAttention、Linux 或 vLLM 而迁移整台环境；原 Windows + Ollama/Transformers 能解决时优先使用。
- 单 GPU 模型串行加载；在线性能实验不与建索引、训练、其他模型推理并行。CPU 默认最多 4 个工作线程，批量前检查可用内存，低于 3 GiB 停止增加任务并释放本项目资源；不得靠频繁分页“硬跑”。D 盘不足 20 GiB 或低于 10% 可用空间时禁止新大下载，优先复用，不删除用户内容。

### 0.5 版本与恢复

保留未提交用户修改，记录 `git status/diff`，在安全的本地分支 `codex/ragscope-v3-diagnostics` 工作；有同名分支先核验，不 reset。每个可验证改动做小提交，不把数据、模型和密钥加入 Git。

保存：`STATUS.json`、`DECISIONS.md`、`RECOVERY.md`、`BUDGET.jsonl`、不可变实验清单和逐题结果。长任务有 PID、日志、心跳、超时、原子提交和恢复点。重启恢复时核验 PID 的创建时间/命令，不信任一个旧 PID 数字。已落盘且身份一致的结果不重跑；失败重试保留原记录。

独立子任务可以只读审计；同一工作目录只允许一个主要写入者。不要递归创建新的代理会话来绕过额度。

### 1.2 必须建立的假设台账

每个假设填写：`id / evidence / hypothesis / counterevidence / test / result / confidence / affected_ids / next_action`。

- H01：部分低 F1 来自多参考答案处理、答案字段或篇幅偏差。
- H02：9B 的模板、thinking 通道、stop、schema、量化或后端有不适配。
- H03：No Context 被严格“仅按材料回答”和空引用 enum 限制，不能诊断模型已有知识。
- H04：Oracle 空上下文泄露不可答状态，或标注证据不完整。
- H05：全库问题缺少论文指代，任务本身不可唯一定位。
- H06：重排打分、窗口聚合、排序或预算打包把好证据移走。
- H07：neighbor 先占预算，挤掉后续高价值核心证据。
- H08：学习路由标签的 F1 噪声、成本偏置/设备混杂和多数类导致全选 BM25。
- H09：LoRA 训练与真实检索上下文分布不匹配，造成拒答策略偏移。
- H10：LoRA loss mask、EOS、截断、引用 ID 或数据存在监督缺陷。
- H11：LoRA 输出变长/重复、结束行为或 adapter 后端导致延迟增加。
- H12：工程可靠性良好，但当前错误诊断尚未转化为足够有效的候选动作。

注意：假设不是 bug 清单。反证成立时应标 `REJECTED`，不要为了让方案显得正确而制造修复。

## 3. S0：保护现场、读取原始证据、建立新留出集

### S0.1 现场核验

1. 核实仓库与实际日期、GPU、内存、D 盘空间；查找当前 v2 的入口和 `LOCAL_RUN_V2.md`。
2. 保存当前代码 commit、dirty diff、文件哈希、已固定的环境与模型清单。
3. 只读定位 `ANALYSIS.json`、`ERROR_CASES.*`、训练报告、路由报告、资源报告、`ACCEPTANCE.json`、全部 frozen inputs/manifests 和逐题 journals。
4. 查找 `train_2b_1024_seed42` 的训练样本、监督 mask、训练日志、adapter 和 `paired_test100` 的原始输出。
5. 不把旧上传 `RAGScope.zip` 当作现有 v2 源码；它可能是改造前版本。
6. 生成 `SOURCE_INVENTORY.json`，每一项明确 `FOUND / MISSING / HASH_MISMATCH`。缺少原始数据时只把相应结论标为待核，不从汇总数字编造逐题记录。

### S0.2 独立重算与语义契约

- 从 journals 独立重算 39 组的 N、失败、F1 和适用分母，核验与 5,520/32 一致；不要以报告互相佐证。
- 核验 `R0/R1/R2/R3` 到方法的映射、完整证据覆盖函数定义、No Context/Oracle 的提示与 schema。
- 给每个 `question_id` 建立实际输入、raw output、解析输出、错误、references、送入模型 token 和来源配置的关联。
- 按题型（抽取、多段自由回答、yes/no、不可答）、问题词、参考长度、预测长度、上下文长度、论文范围分层，不根据低分筛掉记录。
- E8 核对实际可答/不可答数量。`19/100` 若是包含 N/A 的报告口径，保留历史展示并输出正确适用分母，不静默改历史数字。

### S0.3 封存新的验证与测试

v2 已见过的 200 test 题和 LoRA 的 100 题只作为历史诊断/开发材料，不再称未见测试。

- `D_search`：至多 120 个历史诊断问题，可复用旧 dev/test，明确标 `EXPOSED_DIAGNOSTIC`；覆盖模型倒挂、重排退步和拒答变化，不假装代表自然分布。
- `D_confirm`：100 个新的开发确认问题，论文与正式测试、训练不交叉；候选调参只用此集与 D_search。
- `H_QA`：200 个新留出 QASPER 文本可答/不可答问题，尽量至少 70 篇论文。扫描所有 v2/v3 训练、裁判、标签与人工阅读记录，排除被用于调整的题目和相关论文；其原文可为检索提前索引，这是正常 RAG，不等于可以读取测试答案。
- `H_scope`：40 个固定范围/歧义测试；半数具备用户明确论文/题名，半数确实缺少可唯一识别的对象。人工未核验则标合成/AI 审核，不并入官方 QA 分数。
- `H_tasks`：在支持的任务中准备最多 60 个比较/总结问题与关键点、证据来源。尽可能独立论文；与 H_QA 有文档交叉则按论文聚类，不能当成额外独立样本。合成任务不是官方 QASPER。

先通过文档 ID 划分，把 holdout 答案交给仅在终验阶段读取的 evaluator；配置选择代码禁止打开它。若对话助手生成 H_tasks 并读了其答案，这些题不再能宣称操作者盲测，应如实标记并另用 H_QA 做最终主验证。

若没有足够未使用题，下载官方 QASPER 剩余部分并固定 revision/哈希，仍按可解析文本和标注完整性过滤；不得将测试调参后改名为新测试。样本不足据实减少并报告，不能编造。

**阶段产物**：`SOURCE_INVENTORY.json`、`BASELINE_RECOUNT.json`、`EXPOSURE_LEDGER.jsonl`、`SPLITS_V3.json`、冻结题 ID 与评测权限测试。

## 4. S1：不先重跑模型，先纠正评价和分解错误

### S1.1 保留文字基准，修正使用方式

1. 对照 QASPER 官方 schema 与官方 evaluator 实现，核验 multi-reference、yes/no、不可答以及 extractive_spans 的规则；固定所用源码版本。优先复用其纯评价逻辑及测试，不为此安装整个旧AllennLP训练栈。
2. 将 `legacy_token_f1` 完整保留；如果当前实现有误，新增 `qasper_compatible_answer_f1`，并对全部旧答案一致重算，不能只重算某个模型。
3. 显示文字 precision/recall、EM、预测/参考长度、答案类型。检查是否把 JSON、引用标签或解释字段整个拿去与短标准答案比较。
4. 同一新协议把简短答案和补充解释分离，但旧答案不得用看过 gold 的摘要器“润色”后再计分。
5. 错误请求保留在总体质量分母并记零，同时另报成功条件统计；不可答样本使用拒答指标，不混入可答 F1。

### S1.2 加语义指标，但不给相似度“事实真值”地位

对全部可解析旧输出计算 BERTScore，固定模型、层、版本、baseline/IDF 设置；IDF 只能用训练材料估计。多参考规则提前确定，所有模型相同。本轮优先采用 BERTScore 官方实现的英文推荐配置；不盲信自选句向量余弦阈值。

对答案拆分为独立的事实陈述，计算：

- `claim_reference_precision_proxy`：回答陈述被参考答案支持的比例。
- `key_fact_recall_proxy`：参考关键点被回答表达的比例。
- `claim_f1_proxy`：上述两项调和平均，仅为语义参考匹配。
- `context_support_precision_proxy`：回答陈述被实际输入资料支持的比例。
- `citation_support_precision_proxy`：每项引用是否支持它挂接的陈述。
- `citation_completeness_proxy`：需要证据的事实中，有有效支持引用的比例。
- `critical_error_flags`：实体、数值、单位、年份、否定、比较方向、条件和因果关系的冲突。

参考答案未覆盖但原文支持的正确额外事实，单列 `supported_extra`，不要简单当成错误；它也不替代问题要求的关键点。原子化不得丢否定或“在X条件下”这类限制。

不要给所有维度做任意权重的单一“总分”。发布使用第 10 节明确的主指标与护栏。

### S1.3 评判器校准和盲评包

- 先构造 60 组可机器核验的最小对照：同义改写、数字变化、否定、比较方向、错误论文、引用错配、支持不足。已知真假来自构造规则；独立检查构造没有引入歧义。
- 从现有输出固定分层抽取 120 条自然样本，隐藏模型和方案名称，保留采样概率。输出人工审核包，同时用独立模型/NLI做代理审核。
- 推荐优先试 NLI `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli`，加载时读取真实 `id2label`；输入长于模型限制按证据窗口处理，不能截掉结论后判“不支持”。跨窗口联合证据不确定时标 UNKNOWN。
- 现有 Qwen 4B/9B 只对 NLI 不确定或复合陈述进行低预算二次审核。主生成使用哪个模型就记录是否同模型偏差；至少保留不同模型家族的 NLI 交叉信号，不能让生成模型给自己单独定分。
- 对最终候选与基线采用同一裁判、同一输入规则、同一版本；双答案盲评交换 A/B 顺序，保留不一致率。
- 裁判先通过最小对照的至少 90% 工程自检；达不到则不能承担自动发布门槛。这个门槛不代表真实自然语言判断有 90% 准确率。
- 没有人类反馈时不等待任务中断，继续完成自动诊断，但 `human_review_status=NOT_REVIEWED`，结论使用 proxy 名称。UNKNOWN 不从总体中消失，提供上下界/比例。

### S1.4 两个必须分开的可答性

保存三列而非一列：

- `document_answerable`：原论文中是否有答案（官方标注）。
- `visible_context_sufficient`：本次交给模型的材料是否足够（YES/NO/UNKNOWN，注明证据/代理来源）。
- `model_abstained`：模型是否拒答。

证据覆盖为 1 不自动赋 `sufficient=YES`；覆盖小于 1 不自动赋 NO，可能有未标注的等价证据。评判上下文充分性时只看问题和上下文，不以模型是否答对为标签；人工/代理不确定保留。

同时报告：系统层可答题拒答、材料充分仍拒答、材料不足合理拒答、材料不足却肯定作答，以及在固定回答覆盖率下的错误风险。拒答不能通过让所有问题都拒答来“提高安全性”。

No Context 至少拆成：
- `no_context_strict_grounded`：保持只用证据的限制，用于测试拒答/服从。
- `no_context_prior_knowledge_diagnostic`：明确允许已有知识、取消不可能满足的引用要求，仅做诊断。
二者不混算，不拿前者的低 F1 证明模型没有常识。

### S1.5 LoRA 和模型倒挂的旧输出分解

- LoRA 100 对：逐题算 ΔF1，按“新增拒答、仍作答但变差、变好、格式失败”分组。
- 计算每组对整体 ΔF1 的贡献：该组逐题 Δ 总和 / 全部可答 N；四组贡献必须重构总差。
- 对新增 23 条拒答逐一检查实际上下文，分出合理拒答/过度拒答/UNKNOWN。
- 逐题比较输出 tokens、是否达到上限、重复 n-gram、EOS、内容后仍继续生成、实际 TTFT/预填充（若原记录没有则不得补造）、decode tokens/s 与 CPU/GPU 分担。
- 9B 对 2B：在 Oracle 与真实上下文、yes/no 与长自由回答上分别看差值、篇幅和拒答；重新语义计分后再说是否存在内容层倒挂。根据汇总表拒答precision/recall可反推9B的R2大约8个可答题拒答（需journals确认）；即使这8题全变满分，F1最多加8/182≈0.044，仍不足解释与2B约0.150的全部差距。因此不能只查拒答。
- LFM 29 解析失败保留 raw。用纯确定性的 JSON 清理做单列恢复诊断，不改模型原内容，不把恢复当原先成功；看失败是否集中在截断/标签/引用字段/协议不适配。

**阶段产物**：`METRIC_SPEC.md`、`RECOUNT_ALL_OLD.json`、`BLIND_REVIEW_PACKAGE.jsonl`、`JUDGE_CALIBRATION.json`、`ERROR_ATTRIBUTION.md`、LoRA 100 对分组明细。

## 5. S2：优先查生成协议，不急着换更大模型

### S2.1 运行时一致性与冒烟

使用现有 2B/4B/9B Q4 权重，不重下载整套模型。核验：

1. tag→manifest→真实语言权重的映射；post-trained 与 base 不能搞混。
2. 模型配套 tokenizer/chat template，BOS/EOS/stop，是否重复 apply template 或重复插 system。
3. 模板真正收到的 `enable_thinking`、后端 thinking 参数、输出 answer/reasoning 通道；不能只相信配置字符串 `false`。
4. 实际 prompt tokens、最大上下文、输出 512 上限、`finish_reason`、server token 统计与客户端拼接。
5. schema 中答案/拒答分支是否可满足；无上下文时引用 enum 为空是否强制拒答；必要引用和说明是否耗尽输出。
6. 不给 evaluator gold、gold_doc_id、任务真实 answer_type 或 sufficiency 标签混入生成输入。

用 12 个无歧义短夹具（明确事实、否定、数值、需拒答）验证独立模型直接回答、经过当前 pipeline 回答一致。这里不要求模型全对；若同一输入经 pipeline 的行为异常，先修复可验证的包装缺陷。改模板/后端后另立身份，不覆盖历史 G0。

Qwen 官方当前非思考文本采样建议在不同规模间有差别，执行时下载对应**固定版本模型卡**并记录。不要把统一 greedy 认作唯一公平条件，也不要认为官方采样必定更好；二者均测试。对本项目短问答不照搬官方极长输出上限。

### S2.2 有限生成实验

固定 24 道 D_search 问题，覆盖短抽取、yes/no、多段自由回答和不可答。每题准备两种上下文：原 frozen retrieval、审计后的参考证据。不能为某个模型定制证据内容。

| 协议 | 变化 | 目的 |
|---|---|---|
| G0 | 原 v2 协议，greedy/schema/512 | 复核历史协议 |
| G1 | 保持 G0 后端、schema和长度，只明确“answer中给最小充分答案，不加复述和额外说明”，不新增字段 | 查篇幅和答案组织 |
| G2 | 与 G1 同消息和预算，关闭语法约束，仅按同格式要求提示，保留原始错误 | 查 schema 对回答/拒答的影响 |
| G3 | 与 G1 同消息与schema，使用各模型官方非思考建议，seed42/43/44 | 查解码适配；不作为纯参数量因果结论 |

预算：G0–G2 为 3×24×2×3=432 请求；G3 为 3×24×2×3seeds=432；合计864，余量136留运行时/截断核验。历史结果身份完整时可复用 G0，无需为了凑数量重跑。

只有实际 `finish_reason=length` 或原始输出确实截断，才在固定小样本加 512→1024 对照；不要同时更换温度、模板和量化再归因。

另从余量中预留最多36次：12题×3模型，给Oracle添加真实但无关的段落，使长度/证据位置接近原retrieval。旧报告Oracle输入中位约305token，而R2约2136token；不控制长度与噪声，Oracle增益不能全部归因于“找齐更多证据”。保留Oracle_clean、Oracle_padded、retrieval三条件，添加材料不得人为改写成错误事实。

思考模式不是本轮必做项。若非思考协议健康但复杂题证据齐仍错误，可在 2B/4B 的最多12题做“同模型开关thinking”诊断，仍受余量限制，思考消耗的 tokens 记入总预算，不公开或索要隐藏推理作为验收。

### S2.3 精度与后端诊断只对必要模型进行

已有 2B BF16 可作为同模板/同上下文的精度桥接。不能直接拿旧 BF16 prompt-only 和 Q4 schema 表比量化损失。必要时另做 12–24 个成对样本，控制协议后比较；后端不能控制则明确混杂。

9B 不优先下载 BF16（本机难以全驻 GPU且占额外内存）。如果模型卡/模板核验健康且语义评分仍弱，就保留该负结果，不为让大模型胜出而无限折腾。

**S2 过关**：主要包装路径不存在未处理的静默截断/答案通道丢弃/无解 schema；至少一个生成器在明确短证据夹具和 D_confirm 上表现稳定。不是要求所有模型都胜过 2B。

## 6. S3：按错误发生的位置改检索与上下文

### S3.1 先修正任务范围

QASPER 的问题针对特定论文提出。全库中的“他们用了什么数据集？”如果没有题名或选中文档，可能没有唯一目标。

必须保留三个任务条件：

- `PAPER_GIVEN`：用户已选定论文；该输入来源是真实 UI/任务设计，不是从 evaluator 偷取 gold_doc_id。
- `GLOBAL_ANCHORED`：问题明确给出题名/对象，或有用户可见文档范围；属于带定位信息的全库任务。
- `GLOBAL_UNRESOLVED`：全库且缺少可唯一定位的对象；允许输出澄清/候选文档，不能强制随机答某篇论文。

不能把给题目偷偷添加 gold 题名后的成绩，与原无题名 E8直接宣称检索提升。原 E8 保留原条件回归；新条件单独计分。

### S3.2 检索漏斗必须可观测

每题记录并评估：

`输入范围 → 文档候选 → 块候选 → 重排 → 邻接扩展 → 预算打包 → 最终可见材料`。

- `document_recall@1/5/10`：正确对象是否进入候选。
- `evidence_recall@candidate_k`：排序前是否存在支持证据。
- `evidence_survival_after_rerank`：重排丢失多少。
- `evidence_survival_after_pack`：预算/扩展丢失多少。
- 完整参考集合覆盖、连续覆盖、关键事实覆盖 proxy、重复文本比例、题目所需章节覆盖。

Gold 仅在离线 evaluator 中算漏斗损失，不可供在线排序/打包选择。全库问题有多个可接受来源时保留多来源，不用单 gold 给实际正确答案错误扣分。

### S3.3 复用三种已有切法，不重做十一组

初始只保留：现有 R512、F512_O0、P256_1024。每个配置连同清洗、tokenizer、模型、metadata模板、规范坐标形成新索引身份；旧索引只读保留。

加入可还原的 `标题 + 章节路径 + 块正文` 检索文本。生成引用仍指向原文，不把自动补写的摘要当原始证据。先做零生成成本的标题/章节前缀；只有其结果提示缺背景时才试少量本地生成 contextual text。该变体必须与“无前缀”和“仅元数据前缀”分别比较。

### S3.4 两级候选检索与全库旁路

- 文档级：题名/摘要/章节标题的 BM25 与 Dense 找 top5，诊断 top10。
- 文档内：各候选论文取证据块，设上限防止单论文占满全部候选。
- 同时保留一次全库 chunk top候选旁路，以免文档级过滤漏掉答案后无法挽救。
- 合并唯一原文块并使用明确的融合规则；不同索引原始分数不能直接相加。
- 已指定论文时不额外做全库定位，避免白增加耗时。

原 Dense/Hybrid 继续作为固定基线，**不要预先规定 Hybrid 必须赢**。检索融合 α 仅允许小集合 `{0.25,0.5,0.75}`，在 D_search 选后用 D_confirm核对，不能在 H_QA调参。

### S3.5 先诊断 BGE，再引入一个新重排对照

针对现有重排，检查 query/document 参数顺序、降序逻辑、id映射、batch对齐、窗口 query token预算、padding、截断与窗口分数聚合，跑人工可判的排序夹具。报告已经说使用完整512窗口，不能直接指责只读了第一段。

检查 max-window 聚合是否偏爱窗口多的噪声长块；单变量比较 max 与 top2均值，不无限尝试聚合公式。先在同一设备、后端和权重上比较，跨CPU/GPU保留独立结果。

只允许增加一个候选：`Qwen/Qwen3-Reranker-0.6B`。采用官方固定实现：匹配 tokenizer/chat template，按 yes/no token logits 或相应官方 CrossEncoder封装打分，不能把它当普通SequenceClassification模型硬载。所有输入先做12对夹具验证。

候选 top50不足按实际N，不复制填满；重排后top10仅是中间结果，最终仍按 token预算。重排没有证据保留/最终质量收益就不部署。

### S3.6 核心证据优先的上下文打包

旧 neighbor 是必须挑战的基线，不是默认正确方案。

- `K0`：原 none/neighbor 行为，完整保留。
- `K1 core_first`：先分配至少75%预算给排名靠前且去重的核心句/块；邻句扩展最多25%，按实际长度只用必要部分。
- `K2 task_balanced`：比较任务分别给对象A/B预留证据；总结任务按重要章节取候选；保留核心内容与原文定位。

首先同参考预算2048比较，避免“多给一倍文本”伪装算法收益。对入围2条配置再比较2048/4096；8192只在已验证资源和效益需要时作为单独诊断，不全矩阵扩张。

保持否定、实体和条件句完整；去重按 canonical intervals合并，不能重复段落挤满窗口；元数据和引用ID计入预算。先固定入围的实际上下文，再发给多个生成器，同题同条件的文本必须一致。

建议最多6个逐步新增的检索/打包候选，比较采用局部消融而非完整笛卡尔积。最终保留不超过2条进入生成验证。首批40题，明确收益后扩展到D_confirm100；总S3新生成不超过600。

**S3 收益门槛（开发筛选）**：不以92题净增1题作为充分理由。候选须有明确漏斗损失减少，在D_confirm不劣于原主要证据指标超过1pp，且关键事实F1 proxy点提升至少2pp或在线成本显著更低；bootstrap仅辅助不确定性判断，dev选型不是最终显著性宣称。无清楚收益时选更简单的固定路径。

## 7. S4：先做真正不同的工作流，再判断分类器有没有用

### S4.1 问题标签用三个维度

`task = fact / explain / compare / summarize / other`

`evidence_scope = local / multi_section / whole_document / multi_document`

`document_scope = specified / identifiable / ambiguous`

标签可以多维组合，不把“总结两个方法差异”强塞一个互斥类别。`context_sufficient` 是检索后状态，不从问题长度直接预测。初始标签由规则/AI标注，必须标来源与置信度；没有人类确认不叫人工gold。

### S4.2 工作流要真的改变动作

- `W_local`：单次检索、紧凑证据、简短答案。
- `W_compare`：最多拆2个子查询，各自找证据后合并；严格检查两方的比较条件一致，不预先编造结论。
- `W_summary`：按标题/章节覆盖问题指定的要点，先选原始证据，再组织总结。首版不建复杂GraphRAG，不对全库反复生成多层摘要。
- `W_clarify`：缺少论文对象时返回可选文档/澄清请求。本轮Goal不问用户工程选型，不代表产品在缺信息时禁止合理澄清。

保持同一生成器与总上下文/输出预算做机制对照；允许更大预算的产品配置另报成本。比较/总结题要有独立的关键点与证据标注，不能用旧短答案字符串评价长总结。

### S4.3 用策略上界决定是否值得训练

先从D_search/D_confirm中选至少60个适合的已标类别问题，让所有候选工作流实际运行。保存完整每题效用向量，不只保存获胜类别。

报告三种不同上界/参考：
1. 预标任务类别映射到固定工作流（AI标签需披露）。
2. 每题事后挑最佳路径的 hindsight oracle，仅作上界，不能部署或报告真实准确率。
3. 不分类的最佳固定工作流。

如果预标类别策略都没比固定工作流好，停止新分类器训练，保留工作流手动选择及负结果，不用更大router补救无效动作。

### S4.4 条件性分类实验

仅在工作流有用后开展：

- 原有规则和 majority作为底线。
- TF-IDF + 线性分类器。
- 复用现有 query embedding + 小MLP。
- 现有 LSTM 和 Laya 作为可选学习对照；最多再选其中一个，不重训全部体系。

初始至多300个训练问题、100dev；论文与最终test互斥，类别稀少则报告而不伪造。训练任务类型分类不混用“最快检索器”标签。实际路径效用可用来验证映射，而非用历史GPU成本训练CPU部署策略。

报告macro-F1、每类召回、混淆矩阵、置信度校准、分布差异、A/B标签顺序敏感性，以及最重要的端到端质量和成本。

Laya顺序测试使用固定样本对候选顺序进行置换，平均/校准仅在dev定；不要看到test后调回退阈值。回退率95%代表增加开销但几乎没决策，不算路由能力提升。

线上把路由成本计入总成本；大模型自评置信分数不直接作为概率。低置信默认走已验证固定路径；不要默认选择最便宜但明显低质的BM25。

## 8. S5：先证明 LoRA 退步机制，再进行最多两次正式训练

### S5.1 不训练也必须完成的诊断

复用S1的100对输出分解，查训练输入长度、评测实际长度、Oracle/噪声比例、拒答比例和prompt差异。对话中 `eval()` 和 `use_cache=True` 已被检查过，应复核而不是直接指控缺失。

检查至少20条训练样本的真实token和label：

- loss只覆盖应学的assistant输出，prompt/pad被正确mask。
- 不因pad_token等于eos_token而把真实EOS一并mask掉；用位置/attention mask区分padding。
- 结束token受监督；截断没有切掉答案末尾或结束标记。
- 没有只有JSON键、没有事实内容的目标；记录有效答案token比例。
- 训练引用指向可见上下文且事实被支持，不能把原gold_chunk_id放到不同索引。
- 不能把模型生成错误的答案当真值直接训练；来源和验证结果可追溯。
- adapter目标模块真实存在且被更新；记录module名称、参数数、梯度范数。

小样本自检：用8条有明确答案和引用的训练夹具最多20optimizer steps，确认loss/行为方向合理。此结果仅验证监督链路，不是泛化成绩。

### S5.2 速度分解

同后端、同BF16、同模板和上下文，固定24个dev问题比较：base、base+未合并adapter、合并副本。先验证adapter合并不改变预期函数行为，数值误差按固定容差并比较若干logits/生成结果，不要求跨硬件逐位一致。

分别记录加载、预填充、输出token、decode速度、终止原因、真实端到端和host/device资源。合并只写新文件，不覆盖base/旧adapter。不将固定token微基准与自然停止的用户体验指标混算。

若旧adapter在语义质量上仍差，只用它诊断延迟；不为了加速坏模型发布它。

### S5.3 训练触发门槛

只有满足下列条件才重训：
- 主要运行/评判问题已修正。
- 在材料充分的dev问题上仍存在具体可训练的行为问题（过度拒答、漏关键点或格式/引用不稳）。
- 有至少300条可验证训练样本，且实际长度能适配本机。
- 重新训练预计能对准已定位问题，而不只是“训练过了应该更好”。

不满足则标 `NOT_RUN_GATE`，交付诊断即可；不得用伪训练文件充数。

### S5.4 RAFT-inspired 数据，不声称完整复现RAFT

仅复用已有Qwen3.5-2B BF16。首轮不下载4B训练权重。

建议初始混合（训练后不得依据test重改）：
- 60%真实检索且证据充分，使用验证过的参考答案；
- 20%证据充分但带可控干扰（包括跨段证据）；
- 10%简洁Oracle，保持干净输入能力；
- 10%确实上下文不足/论文不可答，目标明确区分“当前材料不足”与“论文未报告”。

这些比例是试验设置，不代表部署真实先验。实际比例和未知剔除数量必须报告，并用自然dev分布校准拒答。不能因证据不完全覆盖就自动造拒答标签。

按部署输入组织训练长度，优先2048总序列预算，保留完整目标和EOS；超长样本通过证据选择而非直接截断目标。8GB不够时先减microbatch=1、启用梯度检查点、缩小rank/target模块。仍不够则用已验证较短方案但明确长度迁移限制，不改WSL上限或侵占其它任务。

采用verified text-only训练路径；库不支持自动assistant mask时写并测试显式collator，不盲填`assistant_only_loss=True`就假定生效。

正式候选最多2个，示例：rank8、alpha16、dropout0.05，学习率1e-5与2e-5；其它参数相同，seed42。架构target模块通过实际`named_modules`选择，不套未经核验的q_proj/v_proj列表。每25步做有限dev生成，不只按loss选checkpoint；总每配置≤1epoch且≤200steps。

dev checkpoint评价同时看关键点、证据支持和材料充分时误拒答；没有实质收益立即停用该候选。最终只允许一个通过的adapter进入H_QA。

### S5.5 部署桥接

先base BF16 vs adapter BF16作因果较清楚的训练对照；再将胜出的合并模型转换为部署Q4，使用新tag。转换前后做固定dev回归，质量/格式退步则不发布。

最终产品性能必须比较 `v2部署Q4` 与 `v3实际部署Q4`，不能用BF16微调成绩代替量化部署结果。转换不支持时可交付BF16候选但显式标阻断，不能声称8GB快速部署已完成。

## 9. S6：冻结后才做最终测试与真实在线验证

### S6.1 锁定不超过三个条件

- B0：保留的v2默认 `2B Q4 + R512 + Hybrid/neighbor`，原检索/生成协议明确冻结。
- C1：在D_confirm选定的最佳无新训练v3配置。
- C2：只有S4路由或S5adapter确实通过开发门槛时保留的一个额外候选；否则不运行。

先生成 `CANDIDATE_LOCK.json`，包含所有数据/指标/模型/模板/索引/阈值和命令身份；从此不依据H_QA改配置、裁判、答案抽取或路由阈值。

在同一个H_QA200上运行B0/C1，C2按门槛触发。同一上下文/协议控制的机制实验与产品级整体对比要区分：产品可以采用更好打包，但需要说明哪些因素共同变化。

同一模型跨检索配置复用冻好的输入；不同模型不允许静默裁短。真正长度不兼容就整体降低预先约定预算并重立实验身份，不只让大模型吃更少证据。

### S6.2 产品专项

- H_scope40：已指定范围是否正确使用、缺对象是否澄清、不偷读gold paper。
- H_tasks最多60：比较任务关键点/双方条件/来源，全文总结章节覆盖/关键点/虚构内容。合成/AI标注结果单列。
- 2B/4B/9B没有必要在所有新工作流上重新做全矩阵；S2解释问题，S6验证一个实用主配置。

### S6.3 在线成本

先关闭答案缓存做主测，另开缓存做单独应用测试。不要把cached retrieval replay总和写成真实E2E。

对固定30个D_confirm问题，B0与C1各3次，共180次正式在线请求，必要预热另计。按成对、交错/随机区组顺序执行，保证同模型驻留、CPU线程与硬件竞争条件一致。索引/模型冷启动单列；多个模型需要独立热测，不能每题加载卸载后称decode很慢。

记录真实请求总耗时、检索、重排、打包、预填充、生成、序列化；测不到TTFT则N/A。P50/P95用完整逐请求分布计算，不能相加各阶段P50。P99样本少仅探索性，不能宣称生产SLA。

### S6.4 统计

按论文聚类配对bootstrap2000次，报告95%区间、实际论文数和适用N。H_tasks/H_scope也按来源文档分组。QASPER短问答、多段比较、总结、歧义处理不可混成一张单一排行榜。

预声明B0 vs C1为主对照，其余探索性；多个主质量结论时进行Holm等预声明校正。工程容差不是统计显著性。

如果最终不通过，不回到H_QA调参再测直到变绿。保留失败，在新campaign和新holdout中再迭代；本轮Goal按真实失败结束。

## 10. 性能门槛：不是换一个更好看的分数

### 10.1 开发筛选

所有候选必须无静默数据/输出损坏。候选相比当前固定基线在D_confirm的 `claim_f1_proxy` 至少+0.02，或在质量非劣前提下真实在线成本明显改善，才进入最终比较。这个只是筛选阈值，不是对外收益证明。

### 10.2 最终质量型候选（工程目标）

- H_QA 的 `claim_f1_proxy` 点提升至少0.05，论文配对95%区间下界>0。
- 保留的文字F1不得下降超过0.01；支持性proxy和引用完整性不得下降超过0.01，关键数字/否定冲突不能因追求相似度被忽略。
- 材料充分时误拒答率不得增加超过0.02；真实请求/格式失败率不超过0.01。
- 相比B0真实在线P50/P95均不超过1.25倍；若质量收益明显但更慢，仅发布“高质量模式”，不得称性能全面提升。

### 10.3 最终效率型候选（另一条独立路径）

- 同一H_QA主要质量差值区间下界不低于-0.01，并满足上述支持性/拒答/失败护栏。
- 真实在线P50至少降低15%，P95不恶化；冷启动与热请求均分开报。

### 10.4 人工未校准时的发布规则

- 没有人工审核但独立自动评判器通过工程校准、文字F1不劣且多个质量轴一致时，可将候选标为 `AUTO_VALIDATED_EXPERIMENTAL`，允许UI实验模式启用并保留一键v2回退。
- 自动语义指标上涨、文字F1明显下降或评判器分歧较大时，标 `HUMAN_REVIEW_REQUIRED`；不自动替换默认，不让Goal无限等待，导出审核包后完成其它交付。
- 只通过pytest、只消除了JSON错误、只换了指标、只多写了报告，都不是“质量型/效率型门槛通过”。
- 这些数值是事前验收目标，不承诺实验一定达到。门槛未过只能如实报告，并保留已经有效的工程修复。

## 11. 执行接口、最小实现与产物

### 11.1 目标接口（需要你实现和测试，不声称现有仓库已具备）

优先复用现有RecordStore、配置、指标和UI，通过少量适配模块接入v3；不为重命名重写全部220份文件。建议目标入口：

```powershell
# 以下命令是待实现并通过 --help / dry-run 验证的目标接口。
. ./scripts/runtime_env.ps1
& '<核验过的v3 Python>' scripts/v3/run_campaign.py --plan configs/v3/campaign.yaml --resume --until acceptance
& '<核验过的v3 Python>' scripts/v3/audit_campaign.py --campaign '<campaign路径>' --independent
```

若仓库已有合适入口，复用并在`COMMANDS.md`记录实际命令；不要为了满足上面名称创造大量空脚手架。

命令必须支持：`--dry-run`输出预算/任务依赖、`--resume`、阶段选择、明确exit code、执行条件评估、失败保留。resume时配置不一致应新建实验，不继续往旧表写。

### 11.2 必须有的回归测试

1. 多参考和yes/no指标、答案字段抽取、N/A/失败分母。
2. 语义最小对照（同义、数字、否定），不把它当真实人评。
3. schema在空上下文和正常上下文均有合理合法输出；答案和思考通道不混淆。
4. gold/reference禁止流入在线pipeline；holdout禁止被训练/选型读取。
5. 文档/块坐标、引用、重排batch映射、分数方向和多窗口聚合。
6. core-first预算、去重、比较对象覆盖、引用元数据计数。
7. 监督mask/EOS/截断/adapter更新与恢复。
8. 原始journals不可覆盖、budget预留原子性、resume幂等。
9. UI空问题、缺对象、无证据、模型不可用、错误清晰呈现，不自动下载/默认Mock。
10. GPU占用识别、只释放本项目进程、结束不自动恢复原训练。

### 11.3 每条记录最低字段

`campaign_id, task_id, question_id, paper_ids, dataset_role, exposure_status, task_type_source, user_scope, config_hash, model_identity, prompt_hash, actual_prompt_tokens, context_intervals, retriever_candidates, rank_scores, packing_drops, raw_response, parsed_response, stop_reason, output_tokens, success, error_type, wall_time, measured_resource, metric_version, judge_identity, proxy_unknowns, budget_ticket`。

无数据用null/UNKNOWN，不填默认0假装实测。流式/非流式时间口径明确。扩展样本不改正式分母。

### 11.4 最终交付（报告要有结论，不堆日志）

1. `EXECUTIVE_SUMMARY_ZH.md`：两页内，解决了什么、未解决什么、是否更好、默认配置是什么。
2. `ROOT_CAUSE_VERDICTS.md`：H01–H12的证据、反证、试验和结论。
3. `QUALITY_SCORECARD.md/json`：B0/C1/C2同题同指标，质量与成本分别展示。
4. `GENERATION_PROTOCOL_DIAGNOSIS.md`、`RETRIEVAL_FUNNEL.md`、`ROUTING_ABLATION.md`、`LORA_DIAGNOSIS.md`。
5. 每类至少3个真实前后案例，包含问题、原文证据、v2/v3回答、为何改善/退步。无实例不得凭空写例子。
6. `HUMAN_REVIEW_PACKAGE.jsonl`及可读Markdown，模型名称隐藏，状态真实。
7. `ACCEPTANCE_V3.json`：执行、性能、发布、人工审核分离；每项关联命令、真实exit code、证据路径。
8. `LOCAL_RUN_V3.md`、最小中文教学说明和回退命令。
9. 新代码、锁文件、测试、模型/数据/论文来源清单、预算账本、恢复说明。
10. `FINAL_RESOURCE_STATE.json`：本项目资源释放、未触碰的其它任务、`USER_MANUAL_RESUME`。

原始22MB错误账本等保留本地，不每次复制进报告；报告引到必要记录，避免“几十页JSON但没有根因结论”。

## 12. 研究依据与落地边界

以下是研究和官方实现来源，不是对本项目收益的保证。执行时只获取必要材料并固定revision/日期，不能无边界追逐最新论文。

[S1] QASPER：数据集角色、问题针对题名/摘要所指论文、答案/证据类型。
https://huggingface.co/datasets/allenai/qasper
https://github.com/allenai/qasper-led-baseline

[S2] BERTScore：上下文向量词级匹配，补充文字重合，不承担事实判断。
https://arxiv.org/abs/1904.09675

[S3] RAGChecker：逐事实的检索/生成诊断，借鉴指标，不照搬大模型裁判开销和阈值。
https://arxiv.org/abs/2408.08067
https://github.com/amazon-science/RAGChecker

[S4] ALCE：答案正确性和引用质量分开评估；合法ID不等于引用支持。
https://aclanthology.org/2023.emnlp-main.398/

[S5] FActScore：原子事实支持性；本项目是面向给定文本的改造，不称原版FActScore复现。
https://aclanthology.org/2023.emnlp-main.741/

[S6] Sufficient Context：按材料充分性区分错误和拒答；不把论文收益照搬成项目目标。
https://arxiv.org/abs/2411.06037
https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/

[S7] Adaptive-RAG 与 MBA-RAG：查询复杂度、流程动作、效用选择；先证明流程差异有用，本轮不新增强化学习训练。
https://aclanthology.org/2024.naacl-long.389/
https://aclanthology.org/2025.coling-main.218/

[S8] RAFT：用相关与干扰材料训练证据使用能力。本轮只借鉴数据分布，未实现原版完整训练配方。
https://arxiv.org/abs/2403.10131
https://gorilla.cs.berkeley.edu/blogs/9_raft.html

[S9] Contextual Retrieval：让块保留文档背景；先用真实标题/章节，再评估生成上下文是否需要，不调用付费Claude API。
https://www.anthropic.com/engineering/contextual-retrieval

[S10] Qwen 官方模型卡：核验模板、采样、嵌入pooling/查询指令和reranker打分方式。
https://huggingface.co/Qwen/Qwen3.5-2B
https://huggingface.co/Qwen/Qwen3.5-4B
https://huggingface.co/Qwen/Qwen3.5-9B
https://huggingface.co/Qwen/Qwen3-Embedding-0.6B
https://huggingface.co/Qwen/Qwen3-Reranker-0.6B

[S11] TRL / PEFT：监督mask和adapter合并方法。参数是否适用以当前模型和已锁环境实际测试为准。
https://huggingface.co/docs/trl/en/sft_trainer
https://huggingface.co/docs/peft/en/package_reference/lora

[S12] 独立NLI候选与ARES：代理评判和少量人工校准的界限。
https://huggingface.co/MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli
https://aclanthology.org/2024.naacl-long.20/

[S13] Goal：持续目标、可验证完成条件，不扩大原有权限。
https://learn.chatgpt.com/docs/long-running-work
