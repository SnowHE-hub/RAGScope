# 怎样读当前结果，而不把工程通过当成质量结论

本页是 2026-10-13 15:12 UTC 的学习快照。实验仍在继续，最终结论应读取本轮完整 manifest、逐条记录和报告。本页不使用尚未完成的 E2/E3 来宣称生成质量提升。

先确认每张表的任务范围。QASPER 主任务由用户明确指定论文，检索只在该论文内进行。因此“返回块所属论文正确”通常容易达到1，不能说明找到了答案证据。全库检索必须先定位论文，难度和分母不同，不能把两个范围的得分混在一起。

“完整参考集合覆盖0.75”表示：在92个证据指标适用的开发问题中，有69个问题的至少一组完整合法参考证据进入了实际打包上下文。不是75%的答案正确，也不是75%的token来自正确内容。连续覆盖则按规范化原文区间衡量每个证据单元覆盖比例，再按已冻结的多参考规则汇总。8个不可回答开发问题和18个不可回答测试问题在这些证据指标中为N/A；它们仍留在拒答和系统错误评估的人口中。

E8 的文档召回是0.37，但完整参考集合覆盖只有0.17。这个例子说明，找到论文与把完整证据交给模型之间还有差距。需要逐条检查是召回内容不足、排序不当还是上下文预算丢掉证据；仅看汇总差值不能断言具体原因，更不能把它归咎于尚未调用的生成模型。

比较方法时，应先核对同样的 query IDs、scope、语料、模型权重、量化、prompt 和上下文预算。E2 的三个模型接收同一冻结 ContextBundle；标题、引用标签和分隔符也计入预算。模型实际聊天模板的输入token数与输出预留必须一起适配上下文上限。参考token预算与模型token预算是两个不同检查，不应互相替代。

当前 2B 本地预检已有真实调用。此快照中的 `pilot_2b_summary.json` 状态仍是 `INCOMPLETE_OR_FAILED`：20个不同dev问题，20条当前身份记录，19次实际token计数一致，1次错误。早期其他模型身份和服务失败也保存在 `generation_pilots.jsonl` 中。预检用于确认后端兼容性、JSON、模板预算和运行资源；它不是冻结测试矩阵，也不用于报告最终模型质量。当前身份为保留官方语言权重、去除未使用视觉投影器的 text-only 本地别名，来源变换和权重哈希必须随结果保存。

一次错误应如何读？transport、timeout、OOM和JSON解析失败是不同事件。加载前RAM guard拒绝不等于发生了GPU OOM。失败保留在总分母；只计算成功请求的平均值必须标明“成功条件下”，不能替代总体值。预算耗尽而根本没有发出请求的任务保持pending，不能伪造一行模型输出。

Oracle只提供原始支持文本，用于区分检索与生成瓶颈；No Context没有检索文本。不可回答问题的Oracle空上下文是实验设计，不是系统自己判断出问题不可回答的证据。E7的位置诊断使用完全相同的证据和干扰片段，仅改变位置；干扰段落来自同论文且不在任何标注证据集合中，其语义无关性尚无人审，结果只作为受控诊断。

最后看不确定性。相同论文中的多个问题相关，因此按论文聚类重抽2000次，而不是把每个问题当作独立样本。配对差异需要完整相同问题集合，包括失败；区间跨零时应如实说明没有明确提升证据。JSON合法率、引用ID可见率和引用覆盖分别回答格式、来源存在和标注支持的问题，不能把其中任何一个直接写成“无幻觉率”。
