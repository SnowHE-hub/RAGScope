# 路由实验：先证明值得选路，再启用默认

RAGScope中的路由器只回答一个小问题：“这次用BM25、Hybrid，还是Hybrid加重排？”它不生成用户答案，也不重新切整库。三条路径共享同一个冻结生成模型和上下文预算，这样才能观察“选检索路径”这一个因素。

代码从 `ragscope/routing/core.py` 开始读。Always-BM25等固定策略是一条不变的路；RuleRouter按可解释的问句特征选择，例如明确的代码标识符可能适合词项检索，比较和原因问题优先重排。规则没有把短问题直接视为简单问题：“Why?”很短，却可能需要多段证据。

学习路由需要先真正运行三条路径。同一个训练问题在三条路径各生成一次，再用答案F1和成本选一个代理标签。举个**教学例子，不是本项目成绩**：三条路径F1为0.70、0.71、0.70，耗时分别为2、4、8秒；因为F1差在预先规定的0.01以内，选择更便宜的第一条。F1只衡量文字重合，所以这个标签只是代理目标，不能称为问题的绝对最佳解法。

`ragscope/routing/learned.py` 包含两条学习基线。TF-IDF把问题中的词变成带权数值，LogisticRegression用线性关系选择路径。MLP先将同一TF-IDF表示降维，再经过一个小隐藏层学习非线性关系。词表只在train拟合，dev用来停止训练和冻结选择，test留到最后。模型没有得到标准答案或证据位置。

`ragscope/routing/lstm.py` 的LSTM是小型文本分类器，不是从头训练一个问答大模型。它按词序读取问题，参数受2M上限约束。它和TF-IDF模型使用的表示、容量不同，因此结果只能比较这些完整方案，不能孤立证明某种神经网络架构更优。若真实标签几乎只有Hybrid，报告会明确显示类别塌缩；增加随机标签去“平衡”会破坏实验。

`ragscope/routing/laya_adapter.py` 使用一个固定的Laya检查点做3选1。候选顺序换三次，是为了检查它是否过分依赖“第一个选项”。输出格式正确并不等于选择正确；概率看起来很高也不表示已经校准。ECE把一组预测信心与代理标签上的实际命中比例比较，Brier衡量整组三类概率与标签的距离。这里校准的目标仍是代理标签。

最后读 `ragscope/routing/evaluate.py`。从已生成的三条路径结果中选一条，可以低成本计算最终答案质量，但这只是“重放”。真实在线延迟必须另跑至少30条，把路由器和必要的模型装卸纳入计时。默认部署要求dev质量相对最强固定路径下降不超过0.01，同时P50端到端延迟至少降低10%。这两个数字是预先选择的工程门槛，不是统计显著性。

功能测试曾用明确的微型合成夹具验证前向、反向和保存恢复；随后正式运行 `20261014_v2_routing` 已使用真实200train/60dev代理标签训练三模型，并在全部决策冻结后重放100test题。源记录与数字以 `docs/execution/ROUTING_REAL_RESULTS.md` 为准。模型能训练成功不等于路由有收益；在线部署门槛未通过前，UI默认保留固定检索路径。

界面实验入口在 `ui/routing_options.py`。选择实验路由时，使用同一索引、冻结的neighbor等上下文策略和最多10块；路由不能顺便更换语料或生成模型。合法长度取自用户指定论文的规范全文 metadata，而不是切块条数，更不会读取该问题的标准答案。全库范围没有单篇长度，记为unknown。界面会展示实际选路、理由、可见输入、路由加载和决策时间。

`default_router`配置本身不能证明值得部署。UI还要读取已校验的dev/在线结果，核对每条策略至少30次真实请求、完整dev质量和P50门槛；缺证据就仍用固定默认。实验选项不等于默认部署，也不等于实验已经完成。交互调用以UI用途进入同一调用账本，单独保存，不追加进冻结的正式test成绩。

实际Laya运行 `20261014_v2_laya` 已完整保存360题×3顺序的1080条决策，另有3条预热。0条调用错误并不等于路由都正确：646条因信心低于固定门槛回退Hybrid，142题的最终选择会随候选顺序变化。默认仍取事先固定的order0，不根据test挑顺序。模型已退出，逐条记录通过独立验收；ECE/Brier和答案质量比较也已完成；这些指标针对真实质量-成本代理标签，不是事实正确性概率。证据见 `docs/execution/LAYA_REAL_RUN.md`。

本轮的具体反例：训练标签中128/200题偏向BM25，三个正常训练完成的学习模型在60dev题上都选择BM25，最终答案F1约0.3806；固定Hybrid约0.4298。不能靠“用了神经网络”推断更好。Laya原order0在dev全部走Hybrid，F1与它相同，但组件重放P50由约1.218秒变成1.900秒；其中57/60次因信心不足回退。三顺序raw choice在59/60个dev问题上会变化，回退后只有26/60改变最终路线，所以回退也会掩盖一部分顺序敏感性。默认顺序和模型超参均没有因test结果改变。
