# 模型大小、内存与有限微调

模型参数越多，通常需要保存更多权重；但显存占用还包括输入激活、KV cache、临时算子和训练状态。因此同一个“2B模型”，推理与训练的内存需求不同，不能只用参数量乘字节数判断能否运行。

量化把权重以更低位数保存，常用于本地推理。BF16 每个数通常占2字节，Q4 主要权重约4bit，但元数据和非量化部分仍占空间。Q4_K_M 是具体量化方案，不等于“模型所有数都4bit”。同名模型如果 revision、量化或后端不同，也不能当作相同实验条件。

上下文越长，模型处理资料和保存中间状态往往越贵。参考 tokenizer 用来公平比较文本量，真实模型 tokenizer 加 chat template 才决定实际输入预算。为512个输出 token 预留空间后，输入不能占满总窗口。这是教学解释，真实 token 与峰值显存以每条运行记录为准。

CPU offload 把部分计算/权重放到系统 RAM。它可能帮助模型装下，也可能明显增加时间并挤压其他程序；显存下降不代表整体资源消耗下降。本任务单卡串行加载，先卸掉本项目上一模型，再加载下一模型；原任务停止和恢复由单独租约与断点证据管理。

LoRA 固定绝大部分基础权重，只训练小型增量矩阵。r 是增量矩阵的秩，alpha 控制缩放，dropout 在训练时随机抑制部分连接。它能调整答案格式和已有能力，但不能补救根本没检索到证据的输入。

本轮冻结初始训练配置在 `configs/v2/lora.json`：BF16、r8、alpha16、dropout0.05、单条 batch、累积8条、长度1024、梯度检查点、学习率1e-4，最多1epoch且200步封顶。梯度检查点用重新计算换显存；梯度累积让多个小 batch 的梯度一起更新参数。

[官方微调说明](https://unsloth.ai/docs/models/qwen3.5/fine-tune) 支持 Qwen3.5 小档 BF16 LoRA，并提示不要把该系列4-bit训练当作默认方案。官方参考显存不是本机实测。这里最多尝试2B和0.8B两条路径，不为了凑成功无限换框架与模型。

训练数据只来自 train 论文。`ragscope/training/data.py` 用模型自己的模板明确哪些 token 属于 assistant；证据和问题的标签设为忽略值。证据或监督答案若放不进预算，整条记录拒绝并保留原因，不能只截掉答案还声称监督完整。dev 用来选 checkpoint，test 只作最终比较。

恢复训练不只是保存 adapter。优化器的动量、学习率调度器、随机状态、训练步数和数据位置都需要保存，否则“续训”可能实际换了训练过程。`checkpoint.py` 对这些状态做完整性哈希并原子发布，只保留本轮自己的最新/最佳断点。

微调前后要用同一 BF16基础模型、同一后端、相同上下文和测试题；拿Q4基础模型与BF16微调模型比较，不能把差异全算作LoRA收益。模型如果在dev变差，就不作为UI默认模型。

## 系统内存、进程占用和WSL上限要分开看

系统RAM与GPU显存是两种资源。CPU embedding即使完全没有用GPU，也要占用系统RAM；浏览器、桌面应用、后台工具和Windows本身同时占用RAM。因此GPU空闲不能证明新模型一定能加载成功。

本机2026-10-14的只读进程快照提供了一个例子：ChatGPT多个进程的工作集合计约2.57GiB，Edge约1.89GiB，Node工具后台约1.57GiB；相应的私有工作集约1.67、0.99、0.84GiB。工作集包含共享页，不应把所有进程工作集相加当作独占物理内存；私有工作集也不涵盖模型映射文件等全部开销。这些是当时的观测，不是每个程序永久占用的数值。原始字节和进程分组保存在 `D:/RAGScope_Runtime/runs/20261014_v2/MEMORY_OCCUPANCY_20261014_1244.json`，该文件的记录时间为01:46:49UTC。

`.wslconfig`中的`memory=12GB`是WSL虚拟机的内存限制，不能仅凭这个数字判断它此刻占了12GB。本轮12:39检查的运行中发行版列表为空；当时降低这个上限不能据此声称回收10GB物理内存。用户随后要求保持上限，配置没有修改，也没有为此启动、关闭或重启WSL。[微软配置说明](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)说明配置在WSL虚拟机启动时生效；本项目实际恢复依据是主机可用RAM、精确进程身份和已校验缓存。

耗时也必须对应实际资源条件。此前12线程CPU结果保留为历史记录；主机重启后按新指令以4线程恢复同一模型，不能直接套用12线程的速度来承诺剩余时间。缓存读取进度较小不代表已保存向量丢失，持久化观察行数与最终index manifest应分别检查。
